# gateway-http Configuration Reference

## Configuration File Locations

| Platform | Path |
|------|------|
| Linux | `/etc/varwof/gateway-http/gateway-http.json` |
| Windows | `%ProgramData%\varwof\gateway-http\gateway-http.json` |

## Top-Level Configuration (Config)

```json
{
  "locale": "zh",
  "listeners": [...],
  "management": {...},
  "short_lived": {...},
  "varwof_core": {...},
  "capability_plugins": {...},
  "authorization_file": "/etc/pki/authz.json",
  "policy_signing": {
    "enabled": true,
    "ca_file": "/etc/pki/issuing-ca.pem",
    "require_admin_ou": true,
    "require": false,
    "sig_suffix": ".sig"
  },
  "tsa_proof_file": "/var/log/gateway/proof.jsonl",
  "tsa_proof_interval_sec": 300
}
```

## Top-Level Configuration Fields

| Field | Type | Description |
|------|------|------|
| `authorization_file` | string | Authorization policy file path (authz.json, OU→role mapping). Once loaded successfully, it becomes the preferred source for RBAC role resolution; when not configured, the hardcoded `gateway:` OU prefix roles are used |
| `capability_schemes` | string | Capability registry directory path (register specification). **Explicitly configuring it enables data-plane capability registry validation** (opt-in, backward compatible): capabilities declared in an AIC must be registered, otherwise the connection is rejected (fail-closed). Directory structure is `vendor/product/v*.json`; on-disk files override embedded schemes of the same name (embedded schemes include varwof/core, varwof/gateway, oracle/mysql, x-vendor/acme, etc.). After editing the JSON, SIGHUP hot reload takes effect immediately. When not configured, the data plane does not validate capability registration |
| `policy_signing` | object | PKCS#7 signature verification configuration for policy files. When enabled, the authorization_file is verified before loading; the signer must be an admin-role certificate issued by this PKI (OU=admin/gateway:admin), and the CA chain is validated by `ca_file` (falls back to the first listener's `ca_cert_file` when absent). With `require: true`, a missing signature causes the load to be rejected |
| `audit_index_file` | string | Audit FTS index file path (bbolt). Setting it enables the `GET /api/v1/gateway/audit/search` full-text search endpoint |
| `risk_monitor` | object | Automatic handling rules for high-risk agents. Setting it enables the reactive closed loop of "behavioral violation → disconnect + revoke": the pipeline records violation signals at behavioral rejection points (plugin deny / parameter overflow / CIDR overflow), and once a rule threshold is reached the gateway performs disconnection (+ revocation) |
| `chain_peers` | ChainPeerConfig[] | No | Cross-gateway audit chain reference peers. Each entry is a peer gateway management API base URL (e.g. `https://gw2:9443`); the gateway periodically fetches the peer's `GET /api/v1/gateway/audit/chain` chain head and writes it into the local `ChainRefStore`, forming a cross-gateway audit evidence DAG (consensus-free ordering). Fields: `name` (peer gateway name), `url` (peer gateway management API base URL); TLS reuses the management API client certificate |

`risk_monitor` fields:

| Field | Type | Default | Description |
|------|------|--------|------|
| `rules[].name` | string | - | Rule name (used in audit/log identification) |
| `rules[].signals` | []string | - | Trigger signals: `plugin_deny`, `parameter_overflow`, `out_of_cidr`; `*` matches all |
| `rules[].threshold` | int | - | Violation count threshold within the window; triggers handling when reached |
| `rules[].window_seconds` | int | 60 | Counting window (seconds) |
| `rules[].action` | string | - | `disconnect` (kick) or `revoke` (kick + conditional revocation) |
| `rules[].reason` | string | - | Handling reason (written to audit and logs) |

`policy_signing` fields:

| Field | Type | Default | Description |
|------|------|--------|------|
| `enabled` | bool | `false` | Enable signature verification |
| `ca_file` | string | First listener's ca_cert_file | Trusted CA chain PEM |
| `require_admin_ou` | bool | `true` | Require the signer to have admin OU (nil = default true) |
| `require` | bool | `false` | When the signature is missing: true = reject, false = downgrade to warning |
| `sig_suffix` | string | `".sig"` | Signature file suffix |

Policy signatures are generated by `core pki policy sign` or `varwof-cli policy sign` (using an administrator certificate).

## ListenerConfig

| Field | Type | Required | Description |
|------|------|------|------|
| `name` | string | **Yes** | Unique listener name |
| `listen` | string | **Yes** | Listen address |
| `protocol` | string | **Yes** | Transport+application protocol: `http1` / `http2` / `h2c` / `grpc` / `ws` / `wss` / `h3` / `quic` (see Protocol table) |
| `tls` | TLSConfig | Conditional | Unified TLS/mTLS configuration block. Required for `protocol=h3/quic` (`cert_file`); required when `tls.mode=mtls` (`ca_cert_file`) |
| `http_ext` | HTTPExtra | No | HTTP-specific extension fields (header-read/response-write timeouts, client cert forwarding, TLS termination) |
| `routes` | []RouteConfig | **Yes** | At least one route |

## RouteConfig

| Field | Type | Description |
|------|------|------|
| `path` | string | **Yes**. URL path pattern (`/prefix/*` or exact match) |
| `target` | string | **Yes**. Backend address (`http://host:port` / `https://host:port` / bare `host:port`; W22: QUIC/H3 paths likewise support all three forms) |
| `allow_methods` | []string | HTTP method allowlist |
| `allow_roles` | []string | RBAC roles |
| `backend_protocol` | string | `h1` / `h2` / `h2c` (default H2 over TLS) |
| `required_capabilities` | []string | Required AIC capabilities |
| `capability_scheme` | string | Capability scheme |
| `capability_prefix` | string | Capability ID prefix |
| `upstream_tls` | object | Backend connection TLS/mTLS configuration (W18). When set, HTTPS backends are verified with a custom CA and carry the gateway client certificate (mutual TLS) instead of being verified against system roots. Fields: `ca_cert_file` (backend CA; leave empty to use system roots), `cert_file`/`key_file` (gateway client certificate), `server_name` (SNI override; leave empty to use the target host), `insecure_skip_verify` (skip backend verification; for testing/self-signed intranets only) |

## TLSConfig

Unified TLS/mTLS configuration block (all fields of the legacy `MTLSConfig` are absorbed here), located in the listener's `tls` field. The `mode` field selects the authentication mode (`none` / `server` / `mtls`). HTTP-specific fields have moved to `http_ext` (see HTTPExtra).

```json
{
  "tls": {
    "mode": "mtls",
    "ca_cert_file": "/etc/pki/ca.pem",
    "cert_file": "/etc/pki/server.pem",
    "key_file": "/etc/pki/server.key",
    "min_tls_version": "1.2",
    "cipher_suites": ["TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384"],
    "crl_url": "http://crl.example.com/ca.crl",
    "crl_refresh_sec": 300,
    "ocsp_cache_ttl_sec": 300,
    "ocsp_fallback": "allow",
    "tsa_url": "http://tsa.example.com",
    "tsa_cert_file": "/etc/pki/tsa.pem",
    "allow_roles": ["gateway:admin", "gateway:ops"],
    "audit_file": "/var/log/gateway/audit.log",
    "audit_max_size_mb": 100,
    "audit_max_backups": 3,
    "max_conns_per_ip": 100,
    "max_conns_per_cert": 50,
    "max_total_conns": 10000,
    "idle_timeout_sec": 300,
    "disconnect_on_expiry": true,
    "require_aic": true,
    "disallow_representative": false,
    "require_user_auth": false,
    "required_capabilities": ["http:proxy"]
  }
}
```

| Field | Type | Default | Description |
|------|------|--------|------|
| `mode` | string | — | TLS authentication mode: `none` / `server` / `mtls`. For `protocol=h3/quic` the default is derived from whether `ca_cert_file` is present (present → `mtls`, absent → `server`); for other protocols the default is `none` |
| `ca_cert_file` | string | Required (mtls) | CA certificate path |
| `cert_file` | string | — | Server certificate |
| `key_file` | string | — | Server private key |
| `crl_url` | string | — | CRL distribution point URL |
| `crl_refresh_sec` | int | 300 | CRL refresh interval |
| `ocsp_cache_ttl_sec` | int | 300 | OCSP cache TTL |
| `ocsp_fallback` | string | `"allow"` | OCSP failure policy. **With `"allow"` (fail-open), the remaining validity of offline certificates is forced to ≤1h (G2(b))** |
| `tsa_url` | string | — | TSA service URL |
| `tsa_cert_file` | string | — | TSA CA certificate |
| `allow_roles` | []string | — | RBAC roles |
| `audit_file` | string | — | Audit log path |
| `max_conns_per_ip` | int | 0 | per-IP limit |
| `max_conns_per_cert` | int | 0 | per-cert limit |
| `max_total_conns` | int | 0 | Global limit |
| `idle_timeout_sec` | int | 0 | Idle timeout |
| `audit_max_size_mb` | int | 100 | Maximum audit size in MB |
| `audit_max_backups` | int | 3 | Number of audit backups |
| `disconnect_on_expiry` | bool | true | Disconnect on certificate expiry |
| `require_aic` | bool | false | Require AIC |
| `disallow_representative` | bool | Same as require_aic | Forbid representative mode |
| `require_user_auth` | bool | false | Require user authentication |
| `cipher_suites` | []string | Secure defaults | TLS cipher suites |
| `min_tls_version` | string | `"1.2"` | Minimum TLS version |

## HTTPExtra (`http_ext` block)

HTTP-specific extension fields, located in the listener's `http_ext` field. All HTTP-related fields of the legacy `MTLSConfig` have moved here.

```json
{
  "http_ext": {
    "read_header_timeout_sec": 30,
    "write_timeout_sec": 300,
    "forward_client_cert": true,
    "forward_client_cert_der": false,
    "tls_termination": true
  }
}
```

| Field | Type | Default | Description |
|------|------|--------|------|
| `read_header_timeout_sec` | int | 30 | Request header read timeout (seconds); 0 = default 30s (W32, slowloris protection) |
| `write_timeout_sec` | int | 300 | Response write timeout (seconds); 0 = default 300s (W32). gRPC/WS long-lived streams write continuously, so small values can kill them mistakenly — tune according to your workload |
| `forward_client_cert` | bool | true | Forward client certificate headers |
| `forward_client_cert_der` | bool | false | Certificate pass-through (B2): forwards the verified client certificate to the backend via `X-Client-Cert-DER`, replacing the deprecated `X-Agent-User` username path (B1); must be used together with core `serve.trusted_gateway_ous` |
| `tls_termination` | bool | true | TLS termination + AIC header injection |

## Backend Protocols

| Protocol | Description |
|------|------|
| `h2` (default) | H2 over TLS |
| `h1` | HTTP/1.1 (disables HTTP/2 negotiation) |
| `h2c` | Cleartext HTTP/2 (no TLS) |

## Protocol

| Protocol | Effective TLS Mode | Description |
|------|-----------|------|
| `http1` | `none` (default) / `server` / `mtls` | HTTP/1.1. Without a `tls` block it is cleartext; `tls.mode=server` enables one-way TLS, `tls.mode=mtls` enables mutual mTLS |
| `http2` | `none` (default) / `server` / `mtls` | HTTP/2 (TLS). **The standard combination for zero-trust mTLS scenarios: `protocol:"http2"` + `tls:{"mode":"mtls",...}`** |
| `h2c` | `none` | Cleartext HTTP/2 (no TLS) |
| `grpc` | `none` (default) / `server` / `mtls` | gRPC (HTTP/2 + protobuf) |
| `ws` | `none` | WebSocket (HTTP upgrade) |
| `wss` | `none` (default) / `server` / `mtls` | WebSocket over TLS |
| `h3` | `server` / `mtls` (built-in TLS 1.3) | HTTP/3 (HTTP over QUIC). `cert_file` required |
| `quic` | `server` / `mtls` (built-in TLS 1.3) | Raw QUIC stream tunnel. `cert_file` required |

> The legacy `tls_mode` field (`plain`/`server`/`mtls`/`h3`/`quic`) has been removed: protocol semantics and TLS authentication mode are now separated. The protocol is specified by `protocol`, and the authentication mode by `tls.mode`.

## CLI Flags

`--config` and `--listener/--route` are mutually exclusive.

### --listener KV Keys

`name`, `listen`, `protocol`, `tls-mode`, `ca-cert`, `cert`, `key`, `crl-url`, `crl-refresh-sec`, `ocsp-cache-ttl-sec`, `ocsp-fallback`, `tsa-url`, `tsa-cert-file`, `audit-file`, `max-conns-per-ip`, `max-conns-per-cert`, `max-total-conns`, `idle-timeout-sec`, `read-header-timeout-sec`, `write-timeout-sec`, `forward-client-cert`, `forward-client-cert-der`, `tls-termination`, `disconnect-on-expiry`, `cipher-suites` (semicolon-separated), `min-tls-version`, `audit-max-size-mb`, `audit-max-backups`

> `tls-mode` is a CLI-compatible key (`protocol` defaults to `http2`). Example: `name=api,listen=:443,protocol=http2,tls-mode=mtls,ca-cert=ca.pem,...`

### --route KV Keys

`listener`, `path`, `target`, `allow-roles` (semicolon-separated)
