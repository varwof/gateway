# gateway-udp Configuration Reference

## Configuration File Location

| Platform | Path |
|------|------|
| Linux | `/etc/varwof/gateway-udp/gateway-udp.json` |

## Top-Level Configuration (Config)

```json
{
  "locale": "zh",
  "listeners": [...],
  "management": {...},
  "short_lived": {...},
  "varwof_core": {...},
  "capability_plugins": {...},
  "authorization_file": "/etc/pki/authz.json",
  "policy_signing": {
    "enabled": true,
    "ca_file": "/etc/pki/issuing-ca.pem",
    "require_admin_ou": true,
    "require": false,
    "sig_suffix": ".sig"
  },
  "tsa_proof_file": "/var/log/gateway/proof.jsonl",
  "tsa_proof_interval_sec": 300
}
```

## Top-Level Configuration Fields

| Field | Type | Description |
|------|------|------|
| `authorization_file` | string | Path to the authz.json policy file. Once loaded successfully, it becomes the preferred source for RBAC role resolution |
| `capability_schemes` | string | Capability registry directory path (register specification). **Explicitly configuring this enables data-plane capability registry validation** (opt-in, backward compatible): capabilities declared in the AIC must be registered, otherwise the connection is rejected (fail-closed). Directory structure `vendor/product/v*.json`; on-disk files override embedded schemes with the same name, and changes to JSON take effect immediately via SIGHUP hot reload. When not configured, the data plane does not validate capability registration |
| `policy_signing` | object | PKCS#7 signature verification configuration for the policy file. When enabled, the authorization_file is verified before loading; the signer must be an admin certificate issued by this PKI (OU=admin/gateway:admin), and the CA chain is validated by `ca_file` (falls back to the first listener's `ca_cert_file` if unset); with `require: true`, a missing signature causes the load to be rejected |
| `audit_index_file` | string | Audit FTS index file path (bbolt). Setting this enables the `GET /api/v1/gateway/audit/search` full-text search endpoint |
| `risk_monitor` | object | Automatic handling rules for high-risk agents. Setting this enables the reactive closed loop of "behavioral violation → kick + revoke": the pipeline automatically records violation signals at behavior-level rejection points (plugin deny / parameter overflow / CIDR overflow), and once a rule threshold is reached, the gateway performs disconnect (+ revoke) |
| `chain_peers` | ChainPeerConfig[] | No | Cross-gateway audit chain reference peer endpoints. Each entry is a peer gateway management API base URL (e.g., `https://gw2:9443`); the gateway periodically fetches the peer's `GET /api/v1/gateway/audit/chain` chain head and writes it to the local `ChainRefStore`, forming a cross-gateway audit evidence DAG (consensus-free ordering). Fields: `name` (peer gateway name), `url` (peer gateway management API base URL); TLS reuses the management API client certificate |

`risk_monitor` fields:

| Field | Type | Default | Description |
|------|------|--------|------|
| `rules[].name` | string | - | Rule name (audit/log identifier) |
| `rules[].signals` | []string | - | Trigger signals: `plugin_deny`, `parameter_overflow`, `out_of_cidr`; `*` matches all |
| `rules[].threshold` | int | - | Violation count threshold within the window; triggers handling when reached |
| `rules[].window_seconds` | int | 60 | Counting window (seconds) |
| `rules[].action` | string | - | `disconnect` (kick) or `revoke` (kick + conditional revocation) |
| `rules[].reason` | string | - | Handling reason (written to audit and logs) |

`policy_signing` fields:

| Field | Type | Default | Description |
|------|------|--------|------|
| `enabled` | bool | `false` | Enable signature verification |
| `ca_file` | string | First listener's ca_cert_file | Trusted CA chain PEM |
| `require_admin_ou` | bool | `true` | Require the signer to have an admin OU (nil = default true) |
| `require` | bool | `false` | When signature is missing: true = reject, false = downgrade to warning |
| `sig_suffix` | string | `".sig"` | Signature file suffix |

Policy signatures are generated by `core pki policy sign` or `varwof-cli policy sign` (using an administrator certificate).

## ListenerConfig

```json
{
  "name": "quic-proxy",
  "listen": ":4433",
  "protocol": "quic",
  "tls": {
    "mode": "mtls",
    "ca_cert_file": "/etc/pki/ca.pem",
    "cert_file": "/etc/pki/server.pem",
    "key_file": "/etc/pki/server.key"
  },
  "udp_ext": {
    "max_pkts_per_ip": 100,
    "max_total_pkts": 10000
  },
  "routes": [{"target": "backend:8080", "allow_roles": ["gateway:admin"]}],
  "read_timeout_sec": 30,
  "max_packet_size": 65535
}
```

| Field | Type | Required | Description |
|------|------|------|------|
| `name` | string | **Yes** | Unique listener name |
| `listen` | string | **Yes** | UDP listen address |
| `protocol` | string | **Yes** | `udp` / `dtls` / `udp+mtls` / `quic` |
| `tls` | TLSConfig | Conditional | Required for non-plaintext modes (dtls/quic need `cert_file`; udp+mtls also needs `ca_cert_file`) |
| `udp_ext` | UDPExtra | No | UDP-specific extension fields (packet rate limits, byte rate limiting, expiry disconnect, etc.) |
| `routes` | []RouteConfig | **Yes** | Backend target list |
| `read_timeout_sec` | int | 30 | Read timeout (seconds) |
| `max_packet_size` | int | 65535 | Maximum UDP packet size |

Mapping between `protocol` and `tls.mode` (when `tls.mode` is unset, it is derived from `protocol`):

| protocol | Default tls.mode | Description |
|----------|---------------|------|
| `udp` | `none` | Plaintext UDP packet forwarding |
| `dtls` | `server` | DTLS encryption (server certificate) |
| `udp+mtls` | `mtls` | DTLS + mutual mTLS |
| `quic` | `mtls` | QUIC transport (built-in TLS 1.3, mTLS via the tls block) |

## RouteConfig

```json
{"target": "8.8.8.8:53", "allow_roles": ["gateway:admin"]}
```

| Field | Type | Description |
|------|------|------|
| `target` | string | **Yes**. Backend address |
| `allow_roles` | []string | RBAC roles |

## TLSConfig

| Field | Type | Default | Description |
|------|------|--------|------|
| `mode` | string | Derived from protocol | `none` / `server` / `mtls`; when unset, derived from `protocol` (udp→none, dtls→server, udp+mtls→mtls, quic→mtls) |
| `ca_cert_file` | string | Required (udp+mtls) | CA certificate path |
| `cert_file` | string | Required (dtls/udp+mtls/quic) | Server certificate |
| `key_file` | string | Required (dtls/udp+mtls/quic) | Server private key |
| `min_tls_version` | string | — | Minimum TLS/DTLS version |
| `cipher_suites` | []string | Secure defaults | DTLS cipher suites |
| `crl_url` | string | — | CRL URL |
| `crl_refresh_sec` | int | 300 | CRL refresh |
| `ocsp_cache_ttl_sec` | int | 300 | OCSP TTL |
| `ocsp_fallback` | string | `"allow"` | OCSP fallback. **With `"allow"` (fail-open), the remaining validity of offline certificates is forced to ≤1h (G2(b))** |
| `tsa_url` | string | — | TSA URL |
| `tsa_cert_file` | string | — | TSA CA certificate |
| `audit_file` | string | — | Audit log path |
| `audit_max_size_mb` | int | 100 | Audit max size in MB |
| `audit_max_backups` | int | 3 | Audit backup count |
| `max_conns_per_ip` | int | 0 | per-IP connection count |
| `max_conns_per_cert` | int | 0 | per-cert connection limit |
| `max_total_conns` | int | 0 | Global connection limit |
| `idle_timeout_sec` | int | 0 | Idle timeout |
| `require_aic` | bool | false | Require AIC |
| `disallow_representative` | bool | Same as require_aic | Disallow representative mode |
| `require_user_auth` | bool | false | Require user authentication |
| `disconnect_on_expiry` | bool | true | Auto-disconnect on certificate expiry (second-level control for the UDP gateway via `udp_ext.disconnect_on_expiry_sec`) |
| `allow_roles` | []string | — | RBAC roles |
| `required_capabilities` | []string | — | Required AIC capabilities |
| `capability_scheme` | string | — | Capability scheme |

## QUIC Mode Special Configuration

QUIC uses the `quic-go` library with flow control windows:
- `InitialStreamReceiveWindow`: 10MB
- `MaxStreamReceiveWindow`: 20MB

ALPN protocols: `h3`, `h3-29` (HTTP3) or `hq`, `hq-29` (QUIC tunnel)
